# web/ — the Migratify landing page

Two static pages, one stylesheet, one small script. No build step, no `npm`,
no framework — the whole point is that it deploys as files and stays fast.

Live at **<https://decoudjuan.github.io/Migratify/>** (Spanish at
[`/es/`](https://decoudjuan.github.io/Migratify/es/)).

```
web/
  index.html       English (canonical, x-default)
  es/index.html    Spanish
  assets/style.css shared stylesheet
  assets/site.js   copy buttons + scroll reveals, ~2 KB
  favicon.svg
  og.png           social card, generated by scripts/build_og.py
  robots.txt
  sitemap.xml
  .nojekyll        do not run the files through Jekyll
```

## Run it locally

```bash
python -m http.server 4000 --directory web
# http://localhost:4000/  and  http://localhost:4000/es/
```

Every link inside the pages is **relative** — `assets/style.css`, `es/`,
`../assets/style.css` — never root-absolute. That is what lets the same files
work at `/` locally and under `/Migratify/` on GitHub Pages. Keep it that way:
a `/assets/...` path silently 404s only in production, which is the worst place
to find out.

## Deploy

`.github/workflows/pages.yml` publishes this folder on every push to `main`
that touches `web/`. It needs one setting, once:

> **Settings → Pages → Build and deployment → Source: GitHub Actions**

Then push, or run the workflow by hand from the Actions tab. The deploy takes
about a minute and the URL is printed in the job summary.

An Actions deploy rather than the branch-and-folder kind because that one can
only serve the repository root or `/docs`, and this is a Python project with a
site in it. If you ever want the simpler toggle instead, rename this folder to
`docs/`, fix the two paths in `web/README.md`, and set Source to
`main` + `/docs`.

## Two things GitHub Pages does not do

- **No clean URLs.** `/es` is a 404; `/es/` is the page. Every link to it ends
  in a slash for that reason, and so does the `hreflang` pair and the sitemap.
- **`robots.txt` is ignored at a subpath.** Crawlers read
  `decoudjuan.github.io/robots.txt`, which belongs to the user-pages repo, not
  this one. The file is kept because it becomes live the moment the site gets
  its own domain, but today the sitemap has to be handed to Search Console
  directly.

## The canonical domain

Every absolute URL — `<link rel=canonical>`, the `hreflang` alternates,
`og:url`, `og:image`, the JSON-LD `url` fields and `sitemap.xml` — points at
`https://decoudjuan.github.io/Migratify/`. If the site moves, rewrite them in
one pass and keep them consistent; a canonical URL pointing somewhere that does
not serve the page is worse than none at all.

```bash
# from the repo root
grep -rl "decoudjuan.github.io/Migratify" web README.md \
  | xargs sed -i "s#https://decoudjuan.github.io/Migratify/#https://your-domain.com/#g"
```

## Regenerating the social card

```bash
python scripts/build_og.py
```

It draws `web/og.png` (1200×630) with Pillow, using fonts from the OS, so run
it on a machine that has Georgia/Consolas or the DejaVu family. It is a
deliberate hand-run step, not CI: the card only changes when the claim or the
version on it does.

## Keeping it honest

The page states specific things about the tool — the weights (0.40 artist,
0.30 title, 0.20 duration), the thresholds (88 / 70 / 4-point tie), the veto
cap at 40, the platform limits, the download size. Those come from
`src/migratify/matching/score.py`, `config.Thresholds`, `CLAUDE.md` and the
published release assets. **If any of them change, change them here too** —
a landing page that oversells the matcher undermines the one promise the
project makes.

The version string appears in the nav badge, the hero terminal, the final CTA,
the footer and the JSON-LD `softwareVersion` of both pages:

```bash
grep -rn "0\.3\.1" web
```
